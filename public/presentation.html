Alur Operasional Terintegrasi: PO, SO, GI, GR & Ledger

📦 Siklus Pengadaan (Purchase Order - PO)

1. Pembuatan PO Draft → Dikirim ke supplier (sent_to_supplier).
2. Goods Receipt (GR): Penerimaan fisik di gudang (parsial/penuh).
3. Menambah stok fisik gudang target dan otomatis mencatat mutasi Receipt di buku besar stock_ledger.

Auto Recalculate Average Cost Multi-Warehouse Allocation
🛒 Siklus Penjualan (Sales Order - SO)

1. Pembuatan SO Draft oleh Sales → Diajukan (pending_approval).
2. Verifikasi independen oleh Admin (approved).
3. Goods Issue (GI): Eksekusi pemotongan stok oleh staf gudang → fulfilled + mutasi Issue di stock_ledger.

Strict Stock Validation Immutable Audit Trail

Slide 05 • Database Integrity Target: 04:30 – 06:00 (90 dtk)

Transaksi ACID & Anti-Oversell (Pessimistic Locking)

🔒 Mengapa Pessimistic Locking?

Pada lonjakan order (*flash sale/concurrent checkout*), query biasa menyebabkan kondisi balapan (*race condition*), membuat stok minus (*lost update*).

Dengan SELECT ... FOR UPDATE, baris record stok gudang dikunci eksklusif sampai transaksi COMMIT atau ROLLBACK.

ACID Guaranteed Tested via ConcurrencyStockIntegrationTest
💻 Mekanisme Kunci pada Goods Issue
// 1. Mulai Transaksi ACID $pdo->beginTransaction(); // 2. Kunci baris stok produk & gudang target SELECT quantity FROM inventory_stocks WHERE product_id = ? AND warehouse_id = ? FOR UPDATE; // 3. Validasi: jika stok < order_qty, batalkan if ($stock < $qty) { $pdo->rollBack(); throw ...; } // 4. Eksekusi potong stok & catat ledger $pdo->commit();
